# Privacy and consent / 隐私与权限

## 本地保存，不代表本地推理

`chat.py` 的外发必须由运行者在每次启动时明确加 `--share-with-openai`。它不在 MCP 里运行，不会自动加入任何宿主。参考实现只连接 `https://api.openai.com/v1/responses`，拒绝重定向；密钥仅来自调用者现有环境。请求设 `store:false`，不传整库、文件路径、同意用语、其他话题或账户身份。不等同于服务商承诺零留存。受控的云验收中，用户端是一次性 GitHub runner，数据均为虚构；其合成问题、回答、模型提案和回执摘要刻意公开。日常使用**不经过 GitHub**。

- MCP 服务只读写你明确配置的本机 SQLite 手记，不运行模型、不请求网络。事件与当前状态均为明文；数据库、可用备份及父目录都需由你保护。文件权限不是加密，也不能抵抗同一操作系统账户下的其他进程。
- 运行 MCP 的 Agent 得到该数据库允许它看到的内容。即使 MCP 在本机启动，Agent 自身仍可能将工具结果交给远端模型、记录至会话日志或扩展到其他工具。因此，“不需云服务”只描述 flyfishPhilo 组件；**是否离线取决于你选的 Agent 和模型。**
- 建议选择该用户专用、仅由本人账户访问的路径。例如 `"$HOME/.local/share/flyfishPhilo/dialogue.sqlite3"`。不要同时让陌生 Agent、公开服务或多个不互信的人访问它。
- 脚本安装器只复制本技能文件到你明确指定的技能目录。若指定个人技能目录，就会在其中新增 `flyfish-philo/`；它不自行挑选目录，也不修改 MCP 注册表、Host 配置、画像或密码库。

## 什么会留下

- 手记每次必须先取得**用户明确同意本题回答保存在本机**；同意短句会与起始问题一起存档。开始前需提醒：Agent 仍能读取该库，所选 Agent 若连接云端，实际 AI 供应商仍可能处理工具结果。用户拒绝本机留存时，不调用 `philo_open`，改为不留存的普通交谈。
- Agent 每次确认它确实收到的回答时，保存该条**用户原文**、所回答的问题和本地回合号；后续读取时，会把问题、最近回答及有限历史交给同一个 Host 模型。要求模型在一问一答外“多保留”时，默认先拒绝而非偷偷构建档案。
- 「不知道」或跳过只记录发生了退出动作，**不保存拒绝理由，也不能作为候选的依据**。题目明确暂停时，只保存那条待答问题，直到用户选择恢复或换题。
- Agent 的问题、提议和最终候选也会留在事件记录中，但来源标签区分用户回答与 AI 草稿。候选证据引用用户回答回合及逐字引文；这是数据库内的可审计对应关系，不是事实核验。
- 只有用户明确邀请整理，才出现候选；只有输入明确匹配“保留这一版”的命令，该版本才出现在当前观点图中。变更和撤回是新事件；同意不是签名，不证明由谁输入。

## 撤回、备份与删除

你可以要求 Host 停止本题或撤回当前观点。AI 候选和已撤回版本仍会保留在本地历史中，以便解释观点如何变化；撤回不等同于删除整段个人原话。若要真正删除私人材料，先选择备份方案，再删除那一份用户专用数据库及其备份文件。若数据已被 Host 或云模型写进会话记录，还应按对应服务商的删除机制处理。关闭浏览器不影响数据库，也不能替你撤销已经送到远程 Host 的内容。

## 不做人格模型

- 问题的数量、沉默、回答节奏或旧版本不会用来推断临床状态、稳定人格、价值排名或政治倾向。
- 一次对话只支撑它实际提到的经历。用户的选例和引文并不是未来记录的强制要求。
- 连接只指向用户曾明确保留的另一条版本。撤回端点后，旧连接显示为过时，不自动复制到新主张。
- 当前状态仍是 SQLite 可编辑记录，而不是篡改检测、可信执行日志或异步代理安全边界。恶意或出错的模型仍可能谎报“用户同意”。因此对话宿主必须确认选择原意；对安全性要求较高者应由独立人类在界面审阅。
- 项目测试与示例仅用合成文字。不要提交 issue/PR/自动化日志中的私人回答、截图、真实个人标识或数据库。

## 可选浏览器工作台的独立边界

旧网页工作簿与本地 Agent SQLite 是两种独立存储，不互相自动导入。网页只在本人决定导出时生成未加密的 JSON/Markdown；整本私人备份不应作为给外部模型的资料包。在网页账本的容量上限内，普通记录须为已采纳版本预留一次短反例和一次撤回；这项保证限引用已有材料、每条理由不超过 256 个 UTF-16 单元，不代表操作系统磁盘写满时 SQLite 仍能写入。
